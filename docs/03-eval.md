# 03 · 评测、账本与边界

> 所有数字默认来自 `data/eval/mock_ledger.json`（确定性 mock 后端），不是真实模型测量值。真实后端已有 50 条分层样本的多轮评测（含非同源 LLM 判定与阈值扫描）：基线结论为负，qwen-plus 压缩输出后出现窄幅正收益；换用更便宜的 qwen-flash 后质量下降，同成功率下不再省钱。详见第 8 节。真实数据不作为生产结论。

## 1. 评测问题

评测只回答三个问题：

1. 在**同一任务流**上，三种架构的总成本、CPST、成功率、升级率、延迟差多少？
2. 级联的"升级"是否真的发生在需要升级的任务上，原因是否可追溯？
3. 浏览器面板展示的数字，是否与本地 Python 账本完全一致？

不回答（本期范围外）：

- 真实模型的质量差异（需要人工标注或任务级评分标准）；
- 学习型路由器的收益；
- 生产流量下的长期成本分布。

## 2. 评测设置

| 项 | 值 |
|---|---|
| 任务流 | 100 条合成任务，固定种子，`simple/medium/complex = 50/30/20` |
| 定价 | 示例价：small 0.15/0.60，frontier 3.00/12.00 USD / 1M tokens |
| 阈值 | 0.66 |
| 小模型重试上限（all_small） | 2 |
| 后端 | 确定性 `MockBackend`（不是真实模型） |
| 成功定义 | 模型响应 `success = true`；任务成功 = 任一尝试成功 |

## 3. 指标定义

| 指标 | 定义 |
|---|---|
| 总成本 `total_cost_usd` | 该策略所有尝试成本之和 |
| CPST `cpst_usd` | 成功任务的总成本 ÷ 成功任务数 |
| 成功率 `success_rate` | 成功任务数 ÷ 总任务数 |
| 升级率 `escalation_rate` | 至少发生一次升级的任务 ÷ 总任务数 |
| 平均延迟 `avg_latency_ms` | 每个任务所有尝试延迟之和的平均 |
| 平均尝试 `avg_attempts` | 每个任务尝试次数的平均 |
| 失败浪费 `failed_cost_usd` | 最终失败任务上花掉的钱 |
| 节省比例 `savings_vs_frontier` | `1 - 本策略总成本 / 全旗舰总成本` |

要点：CPST 的分子只包含成功任务，但成功任务内部**包含**失败重试与升级花费；失败任务的钱单独计入 `failed_cost_usd`，不会从分母里"消失"。

## 4. Mock 结果

| 策略 | 总成本 | CPST | 成功率 | 升级率 | 平均延迟 | 平均尝试 | 失败浪费 | 节省 |
|---|---|---|---|---|---|---|---|---|
| `all_frontier` | $0.235848 | $0.002378 | 98% | 0% | 824 ms | 1.00 | $0.002778 | 0% |
| `cascade` | $0.118222 | $0.001184 | 99% | 29% | 660 ms | 1.29 | $0.001031 | **49.87%** |
| `all_small` | $0.011840 | $0.000113 | 93% | 0% | 394 ms | 1.24 | $0.001361 | 94.98% |

怎么读这张表：

- **级联不是"更便宜的全旗舰"**：它用 29% 的升级率，把 99% 的任务做成功，同时把总成本砍到全旗舰的约一半。
- **全小模型最便宜，但成功率掉到 93%**：失败任务浪费 $0.001361，已经超过级联的全部失败浪费（$0.001031）。便宜的单次价格不等于低的成功成本。
- **全旗舰成功率 98% 并非 100%**：mock 后端也会失败，失败同样产生浪费；这正是 CPST 要纳入失败成本的原因。
- **延迟与成本不同步**：全小模型平均最快，级联居中，全旗舰最慢；升级会在长尾任务上付出延迟代价。

## 5. 口径一致性（Python ↔ 浏览器）

面板不是"预渲染一张表"，而是在浏览器里用原始逐次响应重算：

1. `replay.py` 把每个任务的 small/frontier 尝试原始响应写入 `web/data/ledger.json`；

## 7. 失败案例与可追溯性

- `cascade` 的 fallback 路径：小模型失败 → 旗舰尝试；`reason` 以 `fallback` 开头。
- `cascade` 的质量路径：小模型成功但置信度低于阈值 → 旗舰尝试；`reason` 以 `quality check` 开头。
- 两种路径都由 `test_engine.py` 用脚本化后端强制触发，避免"碰巧通过"。
- `export_trace()` 输出形如 `task_0001 (cascade) -> small ... -> frontier ...` 的决策链，可直接贴进 evidence。

## 8. 真实后端评测（F2.5）：50 条分层样本

真实链路：`qwen-plus`（小模型，带 logprobs）→ `qwen-max`（旗舰），OpenAI 兼容端点（阿里云百炼），价格用官方千问价（`cascade/configs/pricing.qwen.yaml`，汇率 7.2；small 0.111/0.278、frontier 0.333/1.333 USD / 1M tokens）。样本按难度**分层抽取** 50 条（simple 25 / medium 15 / complex 10），两种角色统一 `max_tokens=1024`，阈值 0.85，结果单独保存在 `data/eval/real_ledger.json`，不与 mock 账本合并。

> 20 条试点（均匀抽样、阈值 0.66）的结果已保留为历史对照，见本节末尾。

### 8.1 服务层结果（HTTP 成功口径）

| 策略 | 总成本 | CPST | 成功率 | 升级率 | 相对全旗舰 |
|---|---|---|---|---|---|
| `all_frontier` | $0.019143 | $0.000383 | 100% | 0% | 0% |
| `cascade` | $0.015784 | $0.000316 | 100% | 34% | **17.55%** |
| `all_small` | $0.007486 | $0.000150 | 100% | 0% | 60.89% |

三条策略的 HTTP 成功率都是 100%：百炼通道在这一轮没有出现超时或限流，**HTTP 成功完全无法区分质量**，必须靠判定口径。

### 8.2 判定口径（LLM-as-a-Judge）

裁判换成一个**外部非 Qwen 模型**（非同源：不是 qwen 系列，也不是被测的 qwen-max；模型名属于内部信息，不写入公开仓库，部署时通过 `CASCADE_JUDGE_MODEL` 指定、用 `CASCADE_JUDGE_LABEL` 记录中性标签），严格 rubric、温度 0、判定不感知策略。

| 策略 | 判定成功 | 判定成功率 | CPST（仅服务） | CPST（含判定） | 判定成本 |
|---|---|---|---|---|---|
| `all_frontier` | 39/50 | 78% | $0.000263 | $0.001340 | $0.042023 |
| `cascade` | 25/50 | 50% | $0.000382 | $0.001743 | $0.034019 |
| `all_small` | 14/50 | 28% | $0.000126 | $0.002542 | $0.033827 |

同一批答案用同一裁判重判一次，`all_frontier` 82%→78%、`all_small` 26%→28%（各差 2 条）：50 条样本上 5pp 级的差异并不稳定，本节所有派生数字都以磁盘上这一份判定为准。

### 8.3 阈值扫描：本样本上级联没有优于全旗舰的工作点

用已记录的答案、判定与成本做离线重放（`judge_ledger.py --sweep-only`，**不调用任何模型**）：

| 阈值 | 升级率 | 判定成功率 | 总成本 | CPST |
|---|---|---|---|---|
| 0.66（mock 默认） | 0% | 28% | $0.007486 | $0.000126 |
| 0.85（本次运行） | 34% | 50% | $0.015950 | $0.000351 |
| 0.90 | 74% | 72% | $0.023331 | $0.000407 |
| 0.925 | 96% | 80% | $0.024797 | $0.000380 |
| 0.95 | 98% | 78% | $0.025682 | $0.000382 |
| —— `all_frontier` | 0% | 78% | $0.019143 | **$0.000263** |

结论是负面的，而且很重要：

- **没有任何阈值能同时拿到高成功率和低成本。** 阈值 ≤0.80 时只花 $0.007486 但成功率只有 28%；阈值 ≥0.925 时成功率 80% 与全旗舰 78% 相当，但总花费 $0.024797 比全旗舰的 $0.019143 高 **29.5%**（CPST $0.000380 vs $0.000263，高 44%）——在旗舰成本之上还白付了一遍小模型。
- **平均 token 概率这个信号没有筛选能力。** 它没有识别出"旗舰能救、小模型救不了"的任务：一旦升级，答案就等于全旗舰的答案，成功率封顶在 78%；不升级的任务里大部分是质量失败。级联在这里只是"要么全小模型、要么全旗舰 + 额外开销"。
- **失败不是靠更强模型能解决的。** 50 条里有 17 条（34%）提示词本身缺少必要输入（实时天气、会议纪要/周报正文），任何模型都无法从提示词得出正确内容；这类任务把三条策略的成功率一起压低，也解释了为什么旗舰只有 78%。
- 因此 F2.5 **不能标记为 passing**：级联降本增效的假设在本次真实样本、这个置信度信号下不成立。

### 8.4 判定器自身的三个坑与处理

1. **截断被误判为质量失败**：裁判输出被 `max_tokens` 截断时返回空 content，旧逻辑直接判失败。现在"没有 JSON"算**裁判故障**（`judge_failed`），重试后仍失败则不计入分母。
2. **rubric 奖励编造**：旧 rubric 下，小模型编造会议纪要内容能判过，而旗舰如实说"材料缺失"反被判失败，导致首轮结果反向（small 46% > cascade 40% > frontier 28%）。现在 rubric 明确：任务未提供的日期、数字、纪要内容一律视为无依据，编造必须判失败；材料缺失时说清缺失并给下一步算通过。
3. **判定噪声**：同批答案重判曾让单个策略移动 2/50 条；50 条样本上约 5pp 的差异不能视为稳定结论，阈值工作点必须结合成本结构与扩样复核。

### 8.6 学习型路由器上界验证（零 API 成本）

用已有 50 条标注训练轻量路由器（`cascade/src/router_ceiling.py`：逻辑回归 + 5 折分层交叉验证；特征含难度、缺失输入标签、prompt 长度、自报置信度、输出长度），回答"换一个更好的路由器能不能救"。全程不调用任何模型。

| 策略 | 判定成功率 | 总花费（50 条） | CPST |
|---|---|---|---|
| `all_frontier` | 78% | $0.019143 | $0.000263 |
| **oracle（完美路由）** | 86% | **$0.015005** | $0.000302 |
| 学习路由器（全特征，AUC 0.895） | 80% | $0.019347 | $0.000292 |
| 仅置信度（AUC 0.683） | 78% | $0.0191 | $0.000382 |
| 仅难度（AUC 0.676） | 78% | $0.0191 | $0.000382 |

- **AUC 0.895 是假象。** 要在 78% 成功率上工作，仅置信度和仅难度两个路由器都必须升级 98%–100% 的任务，等于"全旗舰 + 每条都白付一次小模型"，总花费比全旗舰高 39%（旧一版判定下）到 0%（本版判定下）——AUC 高不代表能省钱，能不能省钱取决于升级比例。
- **完美路由器也只省 21.6% 总花费**，而它需要预知"小模型这条会不会答对"——这恰恰是不可预测的部分。
- **算术根因**：小模型在全部 50 条上花 $0.007486；它答对的 14 条里有 10 条旗舰也能答对，只有 4 条真正"只有小模型够用"，所以最多只能省下约 $0.005 的旗舰调用 → 净亏。级联要成立，必须存在**一大批"只有小模型够用"的任务**。
- 这条把 8.3 的结论收紧了：瓶颈**不是路由信号，而是价差、输出长度与任务分布**。换路由器解决不了。
- 口径提醒：CPST 在不同成功率之间不可直接比较——"什么都不升级"的 CPST 最低，因为只有简单任务算成功。因此上表同时给总花费，并在**同等成功率（≥78%）**下比较。

### 8.7 盈亏不等式：级联必须先满足什么（零 API 成本）

"失败即升级"的级联花费是 `S + F_fail`，全旗舰花费是 `F`，所以级联胜出的充要条件是

```
S / F  <  F_pass / F
```

左边是小模型的**有效成本比**（小模型总花费 ÷ 全旗舰总花费），右边是"小模型会答对的那部分任务占旗舰花费的比例"，也就是升级最多能省下的钱。右边同时是天花板：**即使小模型完全免费，也只能省下这个比例**。

用 50 条实测的 token 用量与判定结果重算（`cascade/src/economics.py`，不调用任何模型）：

| 杠杆 | 有效成本比 `S/F` | 级联相对全旗舰 | oracle 上界 |
|---|---|---|---|
| 基线（实测） | 0.391 | **−8.6%** | +21.6% |
| 小模型输出 ×0.75 | 0.296 | +0.9% | +31.2% |
| **小模型输出 ×0.50** | **0.200** | **+10.5%** | +40.7% |
| 小模型单价 ×0.50 | 0.196 | +10.9% | +41.2% |
| 小模型单价 ×0.25 | 0.098 | +20.7% | +50.9% |
| 自托管小模型（×0.10） | 0.039 | +26.6% | +56.8% |
| 输出 ×0.50 + 单价 ×0.50 | 0.100 | +20.5% | +50.7% |

- **当前 0.391 > 可省份额 0.305**，缺口 0.086，这就是 −8.6% 的来源。
- **小模型花费的 98% 是输出 token**：50 条共 26,304 个输出 token、$0.00731，输入只占 $0.00017（平均 prompt 仅 31 token）。所以压输出是最直接的杠杆。
- **可省份额 0.305 由任务分布决定**（只有 14/50 小模型能答对）。免费小模型也只能省 30.5%；要放大收益必须让"只有小模型够用"的任务变多。
- oracle 的 +21.6% 与 8.6 的 21.6% 一致，两条独立算法互相校验。

### 8.8 实测：把小模型答案压到 120 词，级联转正

同一 50 条样本、同一阈值（0.85）、同一对模型，只给小模型加一句 system 指令（`--small-system-prompt`）：

| 指标 | 基线（无限制） | 简短（≤120 词） |
|---|---|---|
| 小模型平均输出 | 526 token | **104 token** |
| `all_small` 判定成功率 | 28% | **44%** |
| `cascade`（阈值 0.85）判定成功率 | 50% | **64%** |
| `all_frontier` 判定成功率 | 78% | 78% |
| 小模型总花费 | $0.007486 | **$0.001768** |
| 有效成本比 `S/F` | 0.391 | **0.089** |
| 同等 80% 成功率下最便宜工作点 | $0.024797（阈值 0.925） | **$0.018454**（阈值 0.90） |
| 该点相对全旗舰（$0.019143 / $0.019848） | **+29.5%** | **−7.0%** |

- 只改一句话，小模型总花费降到 24%，`S/F` 从 0.391 掉到 0.089，越过 8.7 的 0.305 门槛，级联**由亏转盈**。
- 质量没降反升：`all_small` 28%→44%，`cascade` 50%→64%。简短回答少铺垫、少编造，反而更容易通过反编造 rubric。
- 阈值 0.925 时成功率 84%、总花费 $0.018985：比全旗舰便宜 4.3%，同时成功率高 6pp。
- 但这只是"刚翻正"：理想失败信号下可省 47.3%（`economics.py` 同批数据），实测只拿到 4–7%，差额就是信号质量；该点 CPST 与全旗舰几乎持平（$0.000286 vs $0.000280）。
- 边界：单次 50 条、单次判定，重判噪声已显示 ±2 条，4–7% 的幅度需扩样复核；但符号翻转由成本结构（输出长度）决定，不依赖判定。

### 8.9 实测：百炼 qwen-flash + 官方标准价

同一 50 条 task_id、同一简短指令、阈值 0.85、`max_tokens=1024`，只把小模型从 qwen-plus 换成 qwen-flash，旗舰仍为 qwen-max。服务成本使用 `cascade/configs/pricing.qwen-flash.yaml`：百炼北京地域标准实时调用价，flash 输入 ≤128K 档 ¥0.15/¥1.5 每百万输入/输出 token，qwen-max 为 ¥2.4/¥9.6；按 7.2 CNY/USD 换算，不计缓存、Batch 或免费额度。本轮最大 prompt 仅 68 token，全部调用都在第一档。

| 服务侧指标 | plus-brief | flash-brief |
|---|---|---|
| 小模型平均输出 | 103.5 token | **85.4 token** |
| 小模型总花费 | $0.001768 | **$0.000951** |
| `cascade` 总花费（阈值 0.85） | $0.006939 | $0.012931 |
| `cascade` 升级率 | 34% | **56%** |
| `all_frontier` 总花费 | $0.019848 | $0.018866 |

小模型花费下降 46.2%，但阈值 0.85 下升级更多，所以级联服务账单反而上升；50 条小模型与旗舰响应都没有空答案或输出预算耗尽。旗舰响应也重新生成，因此每轮使用自己的旗舰对照，不能把两轮 token 或判定差异都归因于小模型。

非同源 DeepSeek 裁判完成全部 150 个答案判定，`judge_failed=0`。判定与离线经济性对比如下：

| 判定 / 经济性指标 | plus-brief | flash-brief |
|---|---|---|
| `all_small` 判定成功率 | 44% | **10%** |
| `cascade` 判定成功率（实际阈值 0.85） | 64% | **46%** |
| `all_frontier` 判定成功率 | 78% | 80% |
| 有效成本比 `S/F` | 0.089 | **0.050** |
| 可省份额 | 0.562 | **0.218** |
| 理想失败信号节省（离线推算） | 47.3% | **16.7%** |

flash 的阈值扫描中，最高的非全量升级点是 0.95：升级 98%、成功率 78%、总花费 $0.019729，成功率更低且比全旗舰更贵。阈值 1.0 时 100% 升级，成功率才达到 80%，但总花费为 **$0.019817**，比本轮全旗舰 $0.018866 **贵 5.0%**（CPST $0.000270 vs $0.000256）。因此，本轮没有“成功率不低于全旗舰且总成本更低”的阈值工作点。

扫描复用 `all_small` 的独立采样来重放路由，所以其 0.85 行为是 52% 升级 / 44% 成功 / $0.012203，与实际 `cascade` 的 56% / 46% / $0.012931 略有差异；阈值之间的比较统一使用扫描口径。结论是：**更低单价不足以抵消质量下降**。`S/F` 虽然降到 0.050，可省份额却从 0.562 降到 0.218；16.7% 只是知道小模型成败后的离线理想值，不是当前路由器实现的收益。裁判成本另列，且仍按账本旗舰费率估算，不参与上述服务节省结论。

2. ~~减小模型单价~~：已用百炼 qwen-flash 官方标准价实测（8.9）；小模型账单下降，但质量下降使同成功率工作点消失，结果为负。

## 9. 已知限制

- `success` 在 mock 中是概率事件，不代表真实答案质量；真实评测需要任务级 rubric 或人工标注。
- 置信度来自规则 + 稳定抖动（mock）或平均 token 概率（真实）；50 条实测证明平均 token 概率不具备路由筛选能力，生产前必须更换信号。
- 小模型输出长度差异会主导真实成本；真实评测已统一 `max_tokens=1024`，比较策略前必须固定输出预算。
- mock 使用示例价；每个真实账本通过 `pricing_file` 绑定对应模型的百炼官方价与汇率，跨实验比较时必须核对定价表。
- 50 条真实任务仍是小样本：complex 只有 10 条，且 34% 的任务缺少必要输入；基线负结论、plus-brief 的窄幅正收益与 flash-brief 的负结果都需要扩样复核。
- 判定器本身有偏差和成本，判定花费可能远高于服务花费（flash 全小模型尤其明显）；`CPST（含判定）` 与仅服务成本必须分开报告，判定器自身失败单独计数。
